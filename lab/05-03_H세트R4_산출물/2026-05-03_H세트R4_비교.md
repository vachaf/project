# 2026-05-03 H세트 R4 비교

## 1. 실험 개요

- 세트: H세트 Static / Crawler / Scanner-like Noise
- 라운드: R4 — mixed benign + scanner-like
- 실행 방식: Python runner
- runner: `lab/h_set/run_h_r4_mixed_baseline_scanner.py`
- 분석 대상 raw: `lab/05-03_H세트R4_산출물/data/raw/all_2026-05-03_H_R4_kst.json`
- Stage2 결과: `openai-h_r4_mixed_baseline_scanner_stage2_report.md`

H R4의 목적은 정상 browse/static/crawler-like 요청과 scanner-like sensitive path가 같은 `src_ip` / time window에 섞였을 때, pipeline이 이들을 하나의 공격으로 과도하게 묶지 않고 baseline context와 scanner context를 분리해서 설명하는지 확인하는 것이다.

이 실험은 다음을 확인하지 않는다.

- static file 실제 존재 여부
- crawler 진위
- WordPress 존재 여부
- `.env` 또는 backup 파일 노출 여부
- `/server-status` 노출 또는 차단 성공 여부
- 공격 성공 또는 침해 성공 여부
- response body 원문
- request body 원문

## 2. 요청 구성

H R4 runner는 아래 혼합 시나리오를 실행했다.

| Scenario | 목적 | 요청 성격 |
|---|---|---|
| `mixed_basic` | 정상 browse/static + scanner-like path 혼합 | `/`, `/assets/app.js`, `/favicon.ico`, `/.env`, `/wp-login.php`, `/backup.zip`, `/robots.txt` |
| `benign_static_only` | benign/static만 있는 경우 | `/`, `/assets/app.js`, `/assets/style.css`, `/favicon.ico`, `/robots.txt` |
| `scanner_only` | scanner-like sensitive path만 있는 경우 | `/.env`, `/wp-login.php`, `/backup.zip`, `/server-status` |
| `mixed_with_crawler` | static + crawler-like + scanner-like 혼합 | `/`, `/robots.txt`, `/sitemap.xml`, `/products/`, `/.env`, `/backup.zip` |

`all` 기준 총 요청 수는 22건이다. `all` export는 `access=22`, `security=22`, `error=1`로 총 45개 row를 포함했다.

## 4. candidate 결과

대표 candidate는 `/server-status` 403 요청 1건이다.

```text
method=GET
uri=/server-status
status_code=403
verdict_hint=suspicious
user_agent=GenericScanner/1.0
```

주요 reason hints:

```text
sensitive_path:server_status
sensitive_path:no_server_status_exposure_inference
error_status:403(+2)
error_linked(+2)
no_referer_non_browser_error(+1)
```

이 candidate는 Apache 상태 페이지를 대상으로 한 정찰성 요청으로 해석할 수 있다. 다만 `403` 응답만으로 server-status 노출 성공 또는 차단 성공을 확정하지 않는다.

Stage1 결과는 다음과 같다.

```text
verdict=suspicious_scan
severity=low
confidence=high
```

## 5. filtered_out / noise 결과

filtered out 분포는 다음과 같다.

```text
benign_normal_search=12
low_signal_dir_probe=6
low_signal_fuzzing=3
```

이는 정상/정적 요청과 저신호 scanner-like 요청이 섞여 있음을 보여준다.

대표 noise summary:

```text
/.env -> low_signal_dir_probe, count=3
/backup.zip -> low_signal_dir_probe, count=3
/ -> benign_normal_search, count=3
```

해석:

```text
- normal browse/static 요청은 baseline 성격으로 분리됨
- .env / backup.zip 반복은 low-signal sensitive path probe context로 분리됨
- 이 둘을 하나의 성공 공격으로 합치지 않음
```

## 6. context summary 결과

### 6.1 static_baseline_summaries

정상 browse/static 계열 요청이 context로 보존됐다.

```text
normal GET
/assets/app.js
/assets/style.css
/favicon.ico
/robots.txt
/sitemap.xml
```

역할:

```text
static/browse baseline context
```

해석 제한:

```text
static file 존재, robots/sitemap 내용, JS/CSS 파일 내용, file exposure를 단정하지 않음
```

### 6.2 crawler_baseline_summaries

crawler-like 요청이 context로 보존됐다.

```text
Googlebot-like /robots.txt
Googlebot-like /sitemap.xml
GenericCrawler /products/
```

역할:

```text
crawler-like baseline 또는 low-signal crawl context
```

해석 제한:

```text
실제 crawler authenticity, site structure, page existence를 단정하지 않음
```

### 6.3 sensitive_path_probe_summaries

scanner-like sensitive path가 context로 보존됐다.

```text
/.env
/wp-login.php
/backup.zip
/server-status
```

역할:

```text
sensitive path probing context
```

해석 제한:

```text
.env 노출, WordPress 존재, backup 노출, server-status 노출/차단 성공을 단정하지 않음
```

### 6.4 mixed_baseline_scanner_summaries

H R4의 핵심 summary다.

이 summary는 같은 시간창 안에 아래가 함께 존재함을 나타낸다.

```text
- normal/static baseline
- crawler-like baseline
- scanner-like sensitive path
```

역할:

```text
서로 다른 문맥이 같은 src_ip/time window에 섞였지만,
이를 단일 공격 성공으로 합치지 않도록 Stage2에 분리 기준을 제공한다.
```

## 7. Stage2 결과

Stage2는 전반적으로 H R4 목적에 맞게 설명했다.

잘 된 부분:

```text
- 후보 incident는 /server-status 403 한 건으로 제한
- 정상 비교군과 후보 밖 탐색성 요청을 분리해서 설명
- .env / backup.zip / wp-login.php 등은 민감 경로 probing 정황으로 설명
- 실제 파일 노출이나 취약점 악용 성공은 확인되지 않았다고 명시
- known asset IP이므로 내부 테스트/운영 점검 가능성 병기
```

Stage2가 피한 표현:

```text
- .env 노출 성공
- backup.zip 노출 성공
- WordPress 존재 확정
- server-status 노출 성공
- crawler authenticity 확정
- 단일 공격 성공 체인 확정
```

## 9. 남은 관찰점

### 9.1 key_findings severity 표현 불일치

Stage2 보고서의 key finding 중 하나는 `medium`으로 표시됐다.

```text
민감 경로 정찰과 /server-status 탐색이 같은 출발지에서 관찰됨 [medium]
```

하지만 실제 top incident는 다음과 같다.

```text
verdict=suspicious_scan
severity=low
```

즉, 주요 발견의 표현상 severity가 대표 incident보다 조금 높다.

이는 즉시 오류는 아니지만, reporting consistency 관점에서는 개선 후보로 남긴다.

개선 후보:

```text
Stage2에서 key_findings severity가 top incident severity보다 과도하게 높아지지 않도록 guidance 보강
```

### 9.2 filtered_out category 세분화

아래 category는 여전히 넓다.

```text
low_signal_dir_probe
low_signal_fuzzing
benign_normal_search
```

하지만 top-level summaries가 별도 문맥을 제공하므로 현재는 큰 문제는 아니다.

장기 후보:

```text
static_asset_baseline
crawler_like_baseline
sensitive_path_probe_context
mixed_baseline_scanner_context
```

### 9.3 H R4는 선택 실험이었다는 점

H R4는 필수 탐지 기능 검증이라기보다는 narrative 안정성 검증이다. 결과는 기대한 방향으로 나왔으므로, H세트는 현재 범위에서 닫아도 된다.

## 10. 결론

H세트 R4는 목적을 달성했다.

```text
- mixed benign + scanner-like 요청 실행 성공
- static/crawler/sensitive/mixed context가 모두 생성됨
- candidate는 /server-status 403 1건만 low severity로 유지
- 정상 baseline과 scanner-like context가 하나의 공격 성공으로 합쳐지지 않음
- 파일 노출, crawler 진위, page existence, WordPress 존재, attack success 단정 없음
```

따라서 H R4는 완료로 본다.
