# 2026-05-03 H세트 R2 비교

## 1. 실험 개요

- 세트: H세트 Static / Crawler / Scanner-like Noise
- 라운드: R2 — crawler-like baseline
- 실행 방식: Python runner
- runner: `lab/h_set/run_h_r2_crawler_baseline.py`
- 분석 대상 raw: `lab/05-03_H세트R2_산출물/data/raw/all_2026-05-03_H_R2_kst.json`
- Stage2 결과: `openai-h_r2_crawler_baseline_stage2_report.md`

H R2의 목적은 crawler-like User-Agent와 robots/sitemap/product/category browse 요청이 Apache 로그 표면에서 어떻게 남는지 확인하고, 이를 실제 crawler 또는 공격으로 단정하지 않고 baseline/context로 보존할 수 있는지 검증하는 것이다.

이 실험은 다음을 확인하지 않는다.

- 실제 Googlebot/Bingbot 여부
- robots.txt 정책 내용
- sitemap.xml 내용
- site structure 노출 여부
- product/category page 존재 여부
- 공격 성공 여부
- response body 원문
- request body 원문

---

## 2. 요청 구성

H R2 runner는 아래 crawler-like / baseline 요청을 생성했다.

| ID | 요청 | User-Agent | 기대 해석 |
|---|---|---|---|
| H-R2-01 | `GET /robots.txt` | Googlebot-like | crawler-like robots baseline 가능성, 실제 Googlebot 단정 금지 |
| H-R2-02 | `GET /sitemap.xml` | Googlebot-like | crawler-like sitemap baseline 가능성, site structure 단정 금지 |
| H-R2-03 | `GET /products/` | GenericCrawler | product browse-like context, page existence 단정 금지 |
| H-R2-04 | `GET /category/` | GenericCrawler | category browse-like context, page existence 단정 금지 |
| H-R2-05 | `GET /` | browser-like | normal browse baseline |
| H-R2-06 | repeated crawler browse | GenericCrawler | repeated crawl-like context, 공격 단정 금지 |

## 3. prepare 결과

prepare 결과는 다음과 같다.

```text
total_exported_rows=16
selected_source_rows=8
candidate_rows=0
distinct_incident_candidates=0
supporting_events=0
filtered_out_rows=8
filtered_out_non_aggregated_rows=8
static_baseline_summaries=1
crawler_baseline_summaries=1
ip_behavior_aggregates=1
auth_behavior_summaries=0
method_behavior_summaries=0
protocol_anomaly_summaries=0
```

핵심은 `candidate_rows=0`이다. Googlebot-like UA, GenericCrawler, robots/sitemap, products/category browse 요청은 모두 incident 후보로 과승격되지 않았다.

---

## 4. filtered_out 결과

filtered out 분포는 다음과 같다.

```text
low_signal_fuzzing=5
benign_normal_search=3
```

초기 H R2 prepare에서는 `/products/`, `/category/` 계열이 `dir_probe:burst`로만 남는 문제가 있었다. 개선 후에는 crawler-like 문맥에 맞는 hint로 정리되었다.

대표 row의 해석은 다음과 같다.

| 요청 | User-Agent | category | 주요 reason_hints |
|---|---|---|---|
| `/robots.txt` | Googlebot-like | `benign_normal_search` | `crawler_like:googlebot_like_ua`, `crawler_like:robots_txt`, `crawler_like:ua_spoofable`, `crawler_like:no_crawler_authenticity_inference`, `crawler_like:no_crawler_policy_inference` |
| `/sitemap.xml` | Googlebot-like | `benign_normal_search` | `crawler_like:googlebot_like_ua`, `crawler_like:sitemap_xml`, `crawler_like:no_site_structure_inference` |
| `/products/` | GenericCrawler | `low_signal_fuzzing` | `crawler_like:generic_crawler_ua`, `crawler_like:product_browse`, `crawler_like:no_page_existence_inference`, `crawler_like:repeated_crawl_sequence`, `crawler_like:no_attack_inference` |
| `/category/` | GenericCrawler | `low_signal_fuzzing` | `crawler_like:generic_crawler_ua`, `crawler_like:category_browse`, `crawler_like:no_page_existence_inference`, `crawler_like:repeated_crawl_sequence`, `crawler_like:no_attack_inference` |
| `/` | browser-like | `benign_normal_search` | `crawler_like:normal_browse`, `baseline:normal_get` |

## 5. crawler_baseline_summaries 결과

`crawler_baseline_summaries=1`이 생성되었다.

summary 핵심:

```text
context_role=crawler_baseline_context
should_promote_to_candidate=false
interpretation_limit=crawler_ua_spoofable_no_content_or_page_existence_inference
request_count=8
status_counts={200:8}
crawler_like_user_agent_families=[googlebot_like, generic_crawler]
path_categories_observed=[robots_txt, sitemap_xml, product_browse, category_browse, normal_get]
```

reason hints:

```text
crawler_like:googlebot_like_ua
crawler_like:generic_crawler_ua
crawler_like:robots_txt
crawler_like:sitemap_xml
crawler_like:product_browse
crawler_like:category_browse
crawler_like:normal_browse
crawler_like:repeated_crawl_sequence
crawler_like:ua_spoofable
crawler_like:no_crawler_authenticity_inference
crawler_like:no_crawler_policy_inference
crawler_like:no_site_structure_inference
crawler_like:no_page_existence_inference
crawler_like:no_attack_inference
```

이 summary는 crawler-like 요청을 공격 또는 실제 crawler로 단정하지 않고, context-only로 보존한다.

## 6. static_baseline_summaries와 ip_behavior_aggregates

H R2에서는 `static_baseline_summaries=1`도 함께 생성되었다.

```text
asset_categories_observed=[robots_txt, sitemap_xml, normal_get]
```

이는 robots/sitemap/normal GET이 static/baseline 성격도 가지기 때문이다. `crawler_baseline_summaries`와 scope가 다르며 둘 다 context-only이다.

`ip_behavior_aggregates=1`도 생성되었다.

```text
request_count=8
distinct_paths=5
status_4xx_ratio=0.0
status_5xx_count=0
reason_hints=ip_behavior:multi_path_burst
```

이는 같은 src_ip가 짧은 시간에 여러 경로를 요청했기 때문에 생긴 문맥이다. 공격 확정이나 severity 상향 근거가 아니다.

---

## 7. Stage1 결과

H R2에서는 `analysis_candidates=0`이므로 Stage1에서 처리한 candidate는 없다.

```text
processed_candidate_count=0
success_count=0
error_count=0
```

이는 실패가 아니다. H R2의 목적은 crawler-like / baseline 요청이 candidate로 과승격되지 않는지 확인하는 것이며, 이 조건은 충족되었다.

---

## 8. Stage2 결과

Stage2는 H R2 결과를 보수적으로 설명했다.

주요 해석:

- 고신호 incident 없음
- robots.txt / sitemap.xml / products / category / normal GET은 저신호 탐색 또는 기준선 문맥
- crawler-like User-Agent와 내부 자산 IP가 겹치므로 내부 테스트/운영 점검 가능성 병기
- Apache 로그만으로 실제 crawler 정체를 확정하지 않음
- robots/sitemap 내용, site structure, product/category page existence를 단정하지 않음
- 공격 성공이나 노출 성공을 단정하지 않음

Stage2 보고서에는 `crawller-like` 오타가 있었으나, 의미상 해석에는 큰 영향이 없었다. 향후 wording 개선 시 `crawler-like`로 수정할 수 있다.

## 10. 남은 관찰점

현재 구조는 H R2 목적에는 충분하다. 다만 후속 개선 후보는 있다.

1. `low_signal_fuzzing` category가 여전히 남는다.
   - `/products/`, `/category/` 계열은 이제 `crawler_like:*` hints를 갖는다.
   - 기능상 문제는 아니지만, 표현상 `crawler_like_baseline` 또는 `crawler_like_browse_context` category를 검토할 수 있다.

2. Stage2 Markdown에 `crawller-like` 오타가 있었다.
   - 기능상 문제는 아니다.
   - 향후 Stage2 wording 개선 시 수정할 수 있다.

3. `static_baseline_summaries`와 `crawler_baseline_summaries`가 함께 생성된다.
   - robots/sitemap/normal GET이 두 문맥에 걸칠 수 있어 자연스럽다.
   - Stage2는 두 summary를 모두 context-only로 설명해야 한다.

---

## 11. 결론

H세트 R2는 목적을 달성했다.

```text
- crawler-like baseline 실행 성공
- Googlebot-like / GenericCrawler-like 요청이 candidate로 과승격되지 않음
- crawler_baseline_summaries=1 생성
- static_baseline_summaries=1 동시 생성
- robots/sitemap 내용, site structure, page existence, 실제 crawler 여부, 공격 성공 단정 없음
- Stage2가 crawler-like 문맥을 보수적으로 설명
```

따라서 H R2는 완료로 본다.
