## 1. 실험 목적

F세트 R2B는 user enumeration-like / lockout-probing-like 흐름에서 Apache 로그 표면에 응답 차이가 남는지 확인하는 실험이다.

R2B는 공격 성공 여부를 확인하는 실험이 아니다. 핵심은 다음이다.

1. 존재 계정군과 비존재 계정군으로 의도한 요청들이 status/bytes/time 측면에서 차이를 보이는가.
2. lockout probing-like 반복 요청에서 status/bytes/time 변화가 관찰되는가.
3. 차이가 있더라도 user enumeration 성공 또는 lockout 발동으로 단정하지 않는가.
4. 반복 401 요청을 개별 incident로 과도하게 나열하지 않고 auth behavior context로 묶는가.
5. POST body 미확인 한계를 Stage1/Stage2에서 유지하는가.

## 4. 응답 표면 차이 관찰

R2B의 핵심은 existing / nonexistent / lockout-probe 의도 그룹 간 응답 표면 차이 확인이다.

관찰 결과:

| 항목 | 관찰 |
|---|---|
| status_code | 모든 요청 `401` |
| response_body_bytes | 모든 요청 `26` |
| content type | `text/html` |
| distinct path | `/rest/user/login` 1개 |
| POST body visibility | 없음 |

결론:

```text
Apache 로그 표면 기준으로는 존재 계정군, 비존재 계정군, lockout-probe-like 요청군 사이에 뚜렷한 status/bytes 차이가 관찰되지 않았다.
```

따라서 user enumeration 또는 lockout 관련 해석은 아래 수준으로 제한해야 한다.

```text
- user enumeration 성공 단정 불가
- 특정 계정 존재 여부 단정 불가
- lockout 발동 확인 불가
- lockout 우회 성공 단정 불가
- 응답 표면 차이는 제한적 또는 없음
```

## 5. auth_behavior_summaries 결과

Stage2 input 기준 `auth_behavior_summaries`는 다음 문맥을 보존했다.

```text
context_role=auth_behavior_context
should_promote_to_candidate=false
interpretation_limit=post_body_not_visible_no_auth_success_inference
auth_request_count=11
status_counts={"401": 11}
has_repeated_401=true
has_rapid_burst=true
has_mixed_401_200=false
```

`has_rapid_burst=true`는 시간창상 자연스럽다. R2B runner는 11건을 짧은 시간 안에 실행했기 때문이다. 다만 R2B의 해석 중심은 rapid 공격 판정이 아니라 response delta 관찰이다.

문서상 해석 보정:

```text
R2B는 짧은 시간 내 11건이 실행되어 rapid_fail_burst 조건에도 걸렸지만, 실험 해석의 중심은 rapid 공격 판정이 아니라 existing/nonexistent/lockout-probe 간 response surface 차이 관찰이다.
```

## 10. 남은 관찰점

### 10.1 response delta 전용 summary 가능성

현재 R2B는 기존 `auth_behavior_summaries`로 충분히 보존된다. 다만 R2B의 목적이 response surface comparison이므로, 향후 필요하면 다음과 같은 별도 summary를 검토할 수 있다.

```text
auth_response_delta_summary
```

후보 필드:

```text
status_code_by_group
response_body_bytes_by_group
duration_us_by_group
ttfb_us_by_group
surface_delta_observed
account_existence_inference_allowed=false
lockout_confirmation_allowed=false
```

현재 결과에서는 모든 응답이 `401/26B`라 별도 summary의 필요성은 높지 않다.

### 10.2 rapid_fail_burst 표현

R2B는 짧은 시간 내 실행되므로 `rapid_fail_burst` hint가 붙는다. 이는 기술적으로 틀리지는 않지만, R2B 비교 문서에서는 response delta 관찰형 실험이라는 점을 우선한다.

## 11. 결론

F세트 R2B는 목적을 달성했다.

```text
- existing/nonexistent/lockout-probe 의도 그룹 간 status/bytes 차이는 제한적이었다.
- 모든 요청은 401/26B로 유사하게 관찰됐다.
- user enumeration 성공이나 계정 존재 여부는 단정할 수 없다.
- lockout 발동 또는 우회 성공도 단정할 수 없다.
- 반복 auth 실패는 auth_behavior_summaries와 supporting_events로 보존됐다.
- candidate noise는 11개에서 3개로 축소됐다.
```

따라서 R2B는 “response surface 차이 제한적, 성공/존재/lockout 단정 불가”라는 결론으로 정리한다.
