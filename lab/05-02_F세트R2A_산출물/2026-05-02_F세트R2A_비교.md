## 1. 실험 목적

F세트 R2A는 F세트 R1에서 안정화한 `auth_behavior_summaries` 구조가 저속 반복, 정상 browse 혼재, 정상/CI 로그인 baseline에서도 보수적으로 작동하는지 확인하는 실험이다.

주요 확인 축은 다음이다.

1. 저속 401 반복을 rapid burst와 구분하는가.
2. 정상 browse/search 요청 사이에 auth 실패가 섞일 때 auth 요청만 별도 문맥으로 묶는가.
3. Chrome 단독 200 login을 공격으로 과승격하지 않는가.
4. CI/서비스 계정형 단독 200 login을 자동화 공격으로 단정하지 않는가.
5. `auth_behavior_summaries`와 `ip_behavior_aggregates`의 scope를 분리해서 설명하는가.
6. POST body 미확인 및 로그인 성공 단정 금지 원칙을 유지하는가.

## 2. 실행 구성

이번 R2A는 Python runner 기반으로 실행했다.

```bash
python3 lab/f_set/run_f_r2a_auth_scenarios.py \
  --base-url http://192.168.56.105 \
  --scenario all \
  --out lab/05-02_F세트R2A_산출물/runner_logs
```

R2A runner는 총 14개 요청을 생성한다.

| Scenario | Runner label | 요청 구성 | 기대 해석 |
|---|---|---|---|
| F-R2A-01 | `slow_brute_401_x6` | `POST /rest/user/login` 6회, 10초 간격 | low-and-slow auth abuse 가능성 |
| F-R2A-02 | `interleaved_browse_auth_failures` | 정상 browse/search 사이에 `POST /rest/user/login` 401 3회 삽입 | browse는 baseline, auth 실패만 context화 |
| F-R2A-03 | `chrome_single_200_baseline` | Chrome UA 단독 200 login | 정상 login baseline 가능성 |
| F-R2A-04 | `ci_single_200_baseline` | CI-Pipeline UA 단독 200 login | 내부 서비스/CI 가능성, 공격 단정 금지 |

## 4. auth_behavior_summaries 결과

Stage2 input 기준 `auth_behavior_summaries`는 다음 문맥을 보존했다.

```text
context_role=auth_behavior_context
should_promote_to_candidate=false
interpretation_limit=post_body_not_visible_no_auth_success_inference
auth_request_count=11
status_counts={"401":9,"200":2}
has_repeated_401=true
has_rapid_burst=false
has_mixed_401_200=true
```

R2A에서 `has_rapid_burst=false`인 것은 적절하다. R2A는 R1의 rapid burst가 아니라 10초 간격의 저속 반복과 정상 browse 혼재를 관찰하는 실험이기 때문이다.

핵심 평가:

- 저속 반복 auth 실패가 `auth_behavior_summaries`에 보존됐다.
- 401/200 혼재가 보존됐다.
- 200 응답은 성공 근거가 아니라 baseline/context로 남았다.
- auth behavior summary는 context-only로 유지된다.

## 8. 남은 관찰점

### 8.1 Stage1의 단건 표현

Stage1은 representative candidate 단위로 판단하므로 일부 reasoning에서 “단건”이라는 표현이 나온다. 이는 입력 구조상 자연스럽다. Stage2가 `auth_behavior_summaries`를 활용해 반복 문맥을 설명하고 있으므로 현재는 허용 가능하다.

### 8.2 low-and-slow 표현 강화 가능성

Stage2는 “반복 401”과 “brute force 유사 정황”은 언급하지만, R2A의 실험 의도인 low-and-slow를 더 명시적으로 표현할 여지가 있다.

후속 개선 후보:

```text
auth_behavior_summaries.has_repeated_401=true 이고 has_rapid_burst=false 인 경우,
Stage2가 low-and-slow 또는 paced auth probing 가능성을 별도 문구로 설명한다.
```

### 8.3 auth/ip scope 분리 유지

이번 R2A에서는 auth behavior와 ip behavior count가 이전처럼 range로 섞이지 않고 분리돼야 한다. 보고서 문구는 대체로 안정적이지만, 이후 R2B/R2C에서도 계속 확인한다.

F세트 R2A는 목적을 달성했다.

```text
- 저속 반복 auth 실패 보존: 성공
- 정상 browse/search 과승격 방지: 성공
- Chrome/CI 200 baseline 분리: 성공
- candidate noise 축소: 성공
- supporting context 보존: 성공
- POST body 미확인 및 성공 단정 금지: 성공
```

R2A 결과는 R1 개선이 저속/혼합/FP baseline 상황에서도 유지된다는 것을 보여준다. 따라서 R2A는 “prepare + Stage1/Stage2 구조 검증 완료”로 볼 수 있다.
