# 진행상황

- 기준 시점: 2026-05-03
- 문서 역할: 현재 상태를 빠르게 확인하는 짧은 대시보드

## 현재 상태 요약

- Apache 웹 로그 기반 LLM 침입 로그 분석 파이프라인을 유지 중이다.
- 구조는 `export -> prepare -> stage1 -> stage2` 이다.
- 분석 근거는 Apache 로그 표면에 직접 남는 필드로 제한한다.
- raw POST body, response body 원문, DB 결과, 브라우저 실행 여부는 사용하지 않는다.
- `status_code=200`, `text/html`, `response_body_bytes`만으로 성공, 침해, 유출을 단정하지 않는다.

## 최근 확인된 실험 상태

- A~E세트: SQLi, XSS, Traversal, HPP, PHP wrapper, OpenCart search/baseline 검증 완료
- F세트 R1/R2A/R2B: Auth/Login abuse 검증 완료
  - 반복 401, 저속/혼합 auth 실패, response delta 관찰을 보수적으로 정리
  - `auth_behavior_summaries`와 `supporting_events`로 반복 auth 문맥 보존
  - 로그인 성공, 계정 탈취, credential stuffing 성공, lockout 발동 단정 없음
- G세트 R1/R2/R3: HTTP method / protocol anomaly 검증 완료
  - method probing, protocol/malformed request, baseline/FP bait 확인
  - `method_behavior_summaries`, `protocol_anomaly_summaries`로 context-only 보존
  - PUT/DELETE/TRACE/OPTIONS 성공, protocol bypass, malformed request 우회 단정 없음
- H세트 R1/R2/R3/R4: static / crawler-like / scanner-like / mixed noise 검증 완료
  - static/health/browse baseline, crawler-like baseline, scanner-like sensitive path, mixed benign+scanner-like 확인
  - `static_baseline_summaries`, `crawler_baseline_summaries`, `sensitive_path_probe_summaries`, `mixed_baseline_scanner_summaries`로 context-only 보존
  - static file 존재, 실제 crawler 여부, WordPress 존재, 파일 노출, 공격 성공 단정 없음
- G세트 종합 문서와 H세트 종합 문서 작성 완료

## 회귀 검증 상태

- prepare regression: 18 fixtures, `warn=0 fail=0`
- stage dry-run regression: 12 fixtures, `warn=0 fail=0`
- `run_analysis_pipeline.py --dry-run` 기반으로 실제 LLM API 호출 없이 Stage1/Stage2 구조 검증 가능
- `py_compile` 주요 스크립트 통과

## 주요 제한

- raw POST body 분석 불가
- response body 원문 없음
- DB query 결과 없음
- 브라우저 실행 검증 없음
- 로그인 성공, 계정 탈취, credential stuffing 성공은 Apache 로그만으로 단정하지 않음
- PUT 업로드 성공, DELETE 삭제 성공, TRACE/XST 성공, OPTIONS/CORS 취약점은 Apache 로그만으로 단정하지 않음
- malformed request 우회, protocol bypass, 서버 침해 성공은 Apache 로그만으로 단정하지 않음
- static file 존재, robots/sitemap 내용, JS 실행, file exposure, health 정상 여부는 Apache 로그만으로 단정하지 않음
- 실제 crawler 여부, site structure, product/category page existence는 Apache 로그만으로 단정하지 않음
- WordPress 존재, admin access, `.env`/`phpinfo`/`server-status`/backup 노출은 Apache 로그만으로 단정하지 않음
- mixed baseline/scanner-like traffic을 단일 공격 성공으로 단정하지 않음
- 성공, RCE, 유출, 침해를 status/bytes/content-type만으로 단정하지 않음
- 실험환경 특화 rule 금지
  - `lab-*` UA
  - 특정 IP
  - 특정 response size
  - 특정 제품명
  - 특정 route 예외 처리
