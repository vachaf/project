- 기준 시점: 2026-05-05
- 문서 역할: 현재 상태를 빠르게 확인하는 짧은 대시보드

## 현재 상태 요약

- Apache 웹 로그 기반 LLM 침입 로그 분석 파이프라인을 유지 중이다.
- 구조는 `export -> prepare -> stage1 -> stage2` 이다.
- 통합 실행은 `run_analysis_pipeline.py`를 기준으로 하며, `--dry-run`으로 실제 LLM API 호출 없이 Stage1/Stage2 구조 검증이 가능하다.
- 분석 근거는 Apache 로그 표면에 직접 남는 필드로 제한한다.
- raw POST body, response body 원문, DB 결과, 브라우저 실행 여부는 사용하지 않는다.
- `status_code=200`, `text/html`, `response_body_bytes`만으로 성공, 침해, 유출을 단정하지 않는다.
- 현재는 prepare module split / constants mini-move / hints split 1차 / Stage2 prompt compaction / Stage2 report quality lint 튜닝을 마치고 안정화·관찰 단계다.
- Web UI Report Viewer는 Phase 1A/1B 구현 이후 UI polish 계획 문서화까지 완료했고, 구현은 template/CSS 중심 개선을 우선한다.

## 주요 제한

- raw POST body 분석 불가
- response body 원문 없음
- DB query 결과 없음
- 브라우저 실행 검증 없음
- 로그인 성공, 계정 탈취, credential stuffing 성공은 Apache 로그만으로 단정하지 않음
- PUT 업로드 성공, DELETE 삭제 성공, TRACE/XST 성공, OPTIONS/CORS 취약점은 Apache 로그만으로 단정하지 않음
- malformed request 우회, protocol bypass, 서버 침해 성공은 Apache 로그만으로 단정하지 않음
- static file 존재, robots/sitemap 내용, JS 실행, file exposure, health 정상 여부는 Apache 로그만으로 단정하지 않음
- 실제 crawler 여부, site structure, product/category page existence는 Apache 로그만으로 단정하지 않음
- WordPress 존재, admin access, `.env`/`phpinfo`/`server-status`/backup 노출은 Apache 로그만으로 단정하지 않음
- mixed baseline/scanner-like traffic을 단일 공격 성공으로 단정하지 않음
- SQLi는 DB 결과, 인증 우회, 데이터 탈취를 단정하지 않음
- XSS는 브라우저 실행, 쿠키 탈취, 세션 탈취, exfiltration을 단정하지 않음
- file disclosure는 파일 내용 노출, source/config disclosure 성공을 단정하지 않음
- traversal/CMDI는 파일 읽기 성공, command execution 성공, shell access, server compromise를 단정하지 않음
- 성공, RCE, 유출, 침해를 status/bytes/content-type만으로 단정하지 않음
- 실험환경 특화 rule 금지
  - `lab-*` UA
  - 특정 IP
  - 특정 response size
  - 특정 제품명
  - 특정 route 예외 처리

## Web UI Report Viewer 현황

- UI 개선 방향은 프레임워크 전환이 아니라 `FastAPI + Jinja2 + Plain CSS` 유지다.
- `React/Vue/Svelte/Angular`, `Streamlit`, `Tailwind/Bootstrap`, `Docker`는 현재 범위에서 보류다.
- `htmx/Alpine.js`는 작은 인터랙션이 필요해질 때 후속 후보로 둔다.
- 기본 UI 기준은 light theme이며, 이전 스크린샷의 어두운 톤은 Dark Reader 영향이었다.
- UI polish 우선순위:
  - P1: Compare Metrics를 provider panels보다 위로 이동
  - P1: Provider panel 긴 section 접기
  - P1: Header compacting
  - P1: Missing provider panel 시각 일관성
  - P2: Badge color/spacing 정리
  - P2: Table/card border contrast 개선
  - P2: List page card compacting
  - P2: meta-grid spacing 조정
  - P3: hover/focus state 개선
  - P3: section collapse styling 개선
  - P3: small viewport polish
- 예상 수정 범위는 Python logic보다 template/CSS 중심이다.
  - `web/templates/index.html`
  - `web/templates/compare.html`
  - `web/templates/detail.html`
  - `web/static/style.css`
