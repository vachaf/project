# 진행상황

- 기준 시점: 2026-05-24
- 문서 역할: 현재 상태를 빠르게 확인하는 짧은 대시보드

## 현재 상태 요약

- Apache 웹 로그 기반 LLM 침입 로그 분석 파이프라인을 유지 중이다.
- 기본 분석 구조는 `export -> prepare -> stage1 -> stage2` 이고, Web UI 표시용 파생 산출물은 `stage2 -> viewer_payload` 흐름을 사용한다.
- Sliding Window/Rollup/Operator Queue 경로는 기존 Stage1/Stage2를 대체하지 않고, LLM 실행 전 사람이 먼저 볼 summary/review routing layer로 분리했다.
- Apache logs-only evidence boundary의 canonical 기준은 [docs/00_apache_logs_only_evidence_boundary.md](./00_apache_logs_only_evidence_boundary.md)를 따른다.
- 분석 근거는 Apache 로그 표면에 직접 남는 필드로 제한한다.
- raw POST body, response body 원문, DB 결과, 브라우저 실행 여부는 사용하지 않는다.
- `status_code=200`, `text/html`, `response_body_bytes`만으로 성공, 침해, 유출을 단정하지 않는다.
- Web UI는 read-only Security Analysis Console 범위(list/detail/compare/filter + viewer_payload dashboard)로 유지한다.
- Web UI는 execution console이 아니며 pipeline 실행/DB 제어/report rewrite/새 보안 판정 생성은 포함하지 않는다.
- context-only를 finding/incident로 승격하지 않으며, severity/category/verdict 재계산은 하지 않는다.
- Apache 앱 배치별 observability 3-way 비교(PHP sample / OpenCart / Juice Shop reverse proxy)를 완료했고, 공통 `apache_security_io_v1` LogFormat이 세 배치에서 모두 동작함을 확인했다.
- `apache_security_io_v2` 후보는 새 서버에서 별도 검증 중이며, v1 baseline은 그대로 유지한다.
- PHP sample S09 upload-like POST의 `sqli:sql_comment` 단독 신호는 prepare 레벨 narrow guard로 weak upload/sql-comment context 처리되도록 보정했다.
- candidate policy distribution/history는 [docs/design/99_prepare_candidate_policy_distribution_history.md](./design/99_prepare_candidate_policy_distribution_history.md)와 [docs/design/99_observability_run_summary_index.md](./design/99_observability_run_summary_index.md)에 취합했다.
- `explain_prepare_candidates.py`는 `EHxx` error-heavy scenario label을 인식하도록 보강됐고, 재출력에서 `EH01`~`EH12` 표시를 확인했다. prepare/scoring/filtering 변경은 없다.

  - request_id 없는 후보 보존
  - fallback duplicate는 제거하지 않고 `possible_duplicates`로 표시
  - candidate_index merge
  - distributions merge
  - `rollup_input.json`, `dedup_candidates.json`, `rollup_summary.json` 생성
  - `--overwrite` 지원
  - output 3종 모두 존재 시 기본 `skipped_existing`
  - output 일부만 존재 시 기본 실패
  - `uri_family_hints`, `low_and_slow_hints`, Stage1 projection은 v1.0에서 제외
- operator queue 구현 상태:
  - `src/sliding_window_operator_queue.py` v1 추가
  - 입력: `data/rollups/<date>/rollup_*/rollup_input.json`, `rollup_summary.json`
  - 출력: `data/operator_queue/<date>/queue_items.json`, `queue_summary.json`
  - quiet / needs_review / data_quality_check routing
  - data_quality_status 파생
  - llm_eligible 파생
  - llm_required=false 고정
  - top_observed distribution 생성
  - payload-like reason hint allowlist 상수화
  - atomic write 적용
  - output reuse policy 적용
  - Stage1/Stage2/LLM/Web UI/DB/API 실행 없음
  - 보안 verdict/confidence/threat_level/success 판단 생성 없음
