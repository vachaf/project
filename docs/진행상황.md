## 6. 다음 우선순위

### 1순위 — 회귀 fixture 정리

목적:

- B/C/D/E 개선이 서로 깨지지 않도록 자동 또는 반자동 점검 체계를 만든다.
- 실제 raw를 매번 수동으로 찾아 돌리는 방식에서 벗어난다.

권장 fixture:

- B R2B: double decoded SQLi, educational SQL FP, supporting_events
- C: HTML entity XSS, XSS FP review
- D R3: probing sequence summary
- E R2/R2B: PHP wrapper candidate, direct config path context-only
- E R3/R3B: OpenCart search SQLi/XSS, normal search baseline

### 2순위 — `suspicious_file_disclosure` verdict 정식화

목적:

- `php://filter`가 계속 `suspicious_path_traversal`로 흡수되는 문제를 완화한다.
- PHP wrapper/source disclosure 계열을 path traversal과 분리한다.

### 3순위 — 작은 hint 품질 개선

후속 후보:

- benign normal search row에서 `dir_probe:*` hint 제거
- SQLi `xclose` / quote termination hint 추가
- direct config path `200/0B` context hint 세분화
- Stage2 `php://filter/convert.base64-encode` source disclosure 설명 보강
- known asset IP 실행 명령 정리

## 7. 보류 또는 제한 유지

| 항목 | 현재 판단 |
|---|---|
| Time-based SQLi | B세트 R2A에서 실패. DB/앱별 payload 재설계 전까지 보류 |
| POST body payload 분석 | raw POST body가 Apache 로그에 없으므로 성공/실패 판단 확장 금지 |
| response body 원문 기반 성공 판정 | 현재 구조에서는 하지 않음 |
| 특정 실험환경 전용 규칙 | `lab-*` UA, 특정 IP, 특정 response size hard-code 금지 |

## 8. 현재 리스크

- Stage1 verdict taxonomy에 file/source disclosure 전용 verdict가 부족하다.
- OpenAI는 보수적이고 Anthropic은 상대적으로 적극적으로 서술하는 경향이 있어, 최종 문서에서는 Apache 로그 표면 기준으로 보정해야 한다.
- Juice Shop과 OpenCart는 통제된 실험 환경이므로 일반 서비스에 확대할 때는 관찰 가능한 로그 신호로 제한해야 한다.
- 목적 없이 payload를 늘리면 핵심 결론이 흐려질 수 있다.
