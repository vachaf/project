## 6. 다음 우선순위

### 1순위 — 회귀 fixture 정리

목적:

- B/C/D/E 개선이 서로 깨지지 않도록 자동 또는 반자동 점검 체계를 만든다.
- 실제 raw를 매번 수동으로 찾아 돌리는 방식에서 벗어난다.

권장 fixture:

- B R2B: double decoded SQLi, educational SQL FP, supporting_events
- C: HTML entity XSS, XSS FP review
- D R3: probing sequence summary
- E R2/R2B: PHP wrapper candidate, direct config path context-only
- E R3/R3B: OpenCart search SQLi/XSS, normal search baseline

### 2순위 — Stage2 context 보강 마무리

목적:

- prepare top-level의 `ip_behavior_aggregates`를 Stage2 report input/prompt/markdown 에서 context-only 로 직접 참조한다.
- 단독 severity 상향이나 candidate 승격 근거로 사용하지 않는 보수적 해석을 유지한다.

후보 지표:

- request_count
- distinct_paths
- status_4xx_ratio
- distinct_user_agents
- attack_categories_attempted
- sensitive_path_hits

### 3순위 — 작은 hint/패턴 품질 개선

후속 후보:

- SQLi `xclose` / quote termination hint는 반영 완료. false positive 억제를 위해 quote/paren 단독이 아니라 boolean/comment 구조와 결합될 때만 hint를 부여한다.
- PHP wrapper/source disclosure 관련 Stage2 설명은 보강 완료. 이후에는 smoke 검증과 문구 다듬기가 중심이다.
- Log4Shell / SSRF / SSTI / webshell 등 L3 패턴 소량 확장
- known asset IP 실행 명령 정리

## 7. 보류 또는 제한 유지

| 항목 | 현재 판단 |
|---|---|
| Time-based SQLi | B세트 R2A에서 실패. DB/앱별 payload 재설계 전까지 보류 |
| POST body payload 분석 | raw POST body가 Apache 로그에 없으므로 성공/실패 판단 확장 금지 |
| response body 원문 기반 성공 판정 | 현재 구조에서는 하지 않음 |
| Threat intelligence 연동 | 외부 의존성과 재현성 문제로 운영 적용 단계 후보 |
| 공격 패턴 대량 확장 | 회귀 fixture 없이 한 번에 많이 추가하지 않음 |
| 특정 실험환경 전용 규칙 | `lab-*` UA, 특정 IP, 특정 response size hard-code 금지 |

---

## 8. 현재 리스크

- `ip_behavior_aggregates`는 Stage2에서 읽히지만, 아직 별도 회귀 fixture 체계는 prepare 중심이므로 Stage2 smoke 검증은 추가 여지가 있다.
- OpenAI는 보수적이고 Anthropic은 상대적으로 적극적으로 서술하는 경향이 있어, 최종 문서에서는 Apache 로그 표면 기준으로 보정해야 한다.
- Juice Shop과 OpenCart는 통제된 실험 환경이므로 일반 서비스에 확대할 때는 관찰 가능한 로그 신호로 제한해야 한다.
- 목적 없이 payload를 늘리면 핵심 결론이 흐려질 수 있다.
