## 현재 상태 요약

- Apache 웹 로그 기반 LLM 침입 로그 분석 파이프라인을 유지 중이다.
- 기본 분석 구조는 `export -> prepare -> stage1 -> stage2` 이고, Web UI 표시용 파생 산출물은 `stage2 -> viewer_payload` 흐름을 사용한다.
- 통합 실행은 `run_analysis_pipeline.py`를 기준으로 하며, `--dry-run`으로 실제 LLM API 호출 없이 Stage1/Stage2 구조 검증이 가능하다.
- 분석 근거는 Apache 로그 표면에 직접 남는 필드로 제한한다.
- raw POST body, response body 원문, DB 결과, 브라우저 실행 여부는 사용하지 않는다.
- `status_code=200`, `text/html`, `response_body_bytes`만으로 성공, 침해, 유출을 단정하지 않는다.
- Web UI는 read-only Security Analysis Console 범위(list/detail/compare/filter + viewer_payload dashboard)로 유지한다.
- Web UI는 execution console이 아니며 pipeline 실행/DB 제어/report rewrite/새 보안 판정 생성은 포함하지 않는다.
- context-only를 finding/incident로 승격하지 않으며, severity/category/verdict 재계산은 하지 않는다.

## Web UI / Runner 현재 맥락

- viewer_payload read-only dashboard MVP를 유지한다.
  - `/report/{report_id}`(기존 detail) + `/report/{report_id}/payload`(payload dashboard)
  - malformed/empty payload에서도 fallback-safe 렌더링 유지
  - Event Timeline + Selected Event Detail + Related Contexts/Supporting Events preview 유지
  - display-only association 원칙 유지(승격/재판정 없음)
- Related Contexts/Supporting Events 관찰 1차 정리:
  - Related Contexts 매칭은 raw payload 기준으로 유지하고, source IP masking은 display-only toggle로 분리
  - `supporting_events` 0/1 혼재는 viewer/builder 누락이 아니라 prepare 생성 조건 차이로 분리
- `run_analysis_pipeline.py`는 one-shot UX 정리, `--prepare-source-tables auto`, `--run-dir` opt-in 병행 산출물까지 반영 완료했고 현재 안정화 관찰 단계다.
- Web UI run_dir loader Phase 2 설계 문서 작성 완료(`docs/design/99_web_ui_run_dir_loader_phase2_plan.md`, commit `98cef47849defa359ddf9688ff41c566ddc80131`).
  - flat output은 여전히 Web UI 기준이고, `--run-dir`는 opt-in 병행 산출물이다.
  - `runs/*/manifest.json` 기반 loader scan은 설계만 완료됐으며 구현은 아직 하지 않았다.
- Web UI viewer 표시 안정화(모바일/반응형) 반영 완료:
  - `/report/{report_id}` 표 섹션(notable_incidents/notable_source_ips/recommended_actions) 모바일 카드형 가독성 개선
  - `/report/{report_id}/payload` Contexts Preview 모바일 카드형 개선
  - Payload Event Timeline: 960px 이하 카드형 전환 유지, 1181~1280px 폭 압박 완화, category badge 잘림 완화
  - Payload Event Timeline 표시 순서를 time 오름차순으로 정렬(`log_time -> display_time`, unknown/미파싱은 뒤)
  - row 클릭 detail 불일치 없이 수동 확인 기준 통과, 큰 이상은 발견하지 못함
  - 원칙 유지: read-only viewer, 분석/판정/연결 로직 변경 없음
