# 진행상황

- 기준 시점: 2026-05-28
- 문서 역할: 현재 상태를 빠르게 확인하는 짧은 대시보드

## 현재 상태 요약

- Apache 웹 로그 기반 LLM 침입 로그 분석 파이프라인을 유지 중이다.
- 기존 기본 분석 구조는 `export -> prepare -> stage1 -> stage2 -> viewer_payload` 흐름이다.
- 교수님 피드백 반영 후 상위 운영 방향은 DB-backed 웹 기반 로그 분석 플랫폼으로 정리했다.
- 새 상위 흐름은 `Apache 로그 수집 -> MariaDB 적재 -> Web UI 분석 작업 등록 -> Analysis Agent 실행 -> Stage1/Stage2/viewer_payload 생성 -> Web UI 결과 확인`이다.
- `analysis_jobs queue`는 사용자가 등록한 분석 실행 queue이고, 기존 `operator queue`는 rollup 이후 사람이 검토할 관찰 대상 queue다.
- DB-backed MVP의 기본 `analysis_mode`는 `full_report`이며, Stage1/Stage2/viewer_payload 생성과 report/artifact 저장까지 완료되어야 `SUCCEEDED`로 본다.
- Sliding Window/Rollup/Operator Queue 경로는 기존 Stage1/Stage2를 대체하지 않고, full report job 내부의 summary/review routing artifact로 연결할 수 있다.
- Apache logs-only evidence boundary의 canonical 기준은 [docs/00_apache_logs_only_evidence_boundary.md](./00_apache_logs_only_evidence_boundary.md)를 따른다.
- raw POST body, response body 원문, DB 결과, 브라우저 실행 여부는 사용하지 않는다.
- `status_code=200`, `text/html`, `response_body_bytes`만으로 성공, 침해, 유출을 단정하지 않는다.
- context-only를 finding/incident로 승격하지 않으며, Web UI에서 severity/category/verdict를 재계산하지 않는다.

### 설계 결정

- DB는 MariaDB/MySQL 기준으로 정리했다.
- 로그 source table은 기존 3개 구성을 유지한다.
  - `apache_access_logs`
  - `apache_security_logs`
  - `apache_error_logs`
- operation/control table 후보를 정리했다.
  - `users`
  - `analysis_jobs`
  - `analysis_reports`
  - `job_events`
  - `log_collection_checkpoints`
- 시간 저장 기준:
  - MariaDB의 `log_time`, `time_from`, `time_to`는 UTC naive `DATETIME(3)` 기준으로 저장한다.
  - Web UI 입력/표시는 기본 `Asia/Seoul`로 둔다.
  - sliding window / rollup artifact label과 window_id/rollup_id는 기존 repo 흐름과 맞춰 `Asia/Seoul` 기준을 유지한다.
- MVP 기본 `analysis_mode`는 `full_report`다.
  - export
  - prepare
  - sliding window / rollup 후보
  - operator queue 생성 후보
  - Stage1
  - Stage2
  - viewer_payload 생성
- `analysis_jobs.status=SUCCEEDED`는 Stage1, Stage2, viewer_payload 생성과 report/artifact 저장이 완료된 상태로 정의했다.

### Log shipper UTC 보정

- `src/apache_log_shipper.py`에서 access/security 로그는 기존처럼 timezone-aware timestamp를 UTC naive `DATETIME(3)`로 저장한다.
- `src/apache_log_shipper.py`의 error log timestamp 처리도 UTC 저장 기준에 맞췄다.
- `APACHE_ERROR_LOG_TIMEZONE` 환경변수를 추가했다.
  - 기본값: `Asia/Seoul`
- timezone 없는 error log timestamp는 `APACHE_ERROR_LOG_TIMEZONE` 기준으로 해석한 뒤 UTC naive `DATETIME(3)` 문자열로 저장한다.
- timezone 포함 error timestamp 포맷도 수용한다.
- smoke 확인:

```text
input: 2026-05-28 18:30:00.000
parse_error_time: 2026-05-28 18:30:00+09:00
to_mysql_datetime: 2026-05-28 09:30:00.000
```

### Scheduler / Window

- `src/sliding_window_scheduler.py --mode planner`: window 목록과 `data/windowed/YYYY-MM-DD/sw_HHMM_HHMM/` 경로 계산
- `src/sliding_window_scheduler.py --mode export`: window별 `export.json` 생성
- `src/sliding_window_scheduler.py --mode prepare`: window별 `export.json`을 입력으로 `prepare_llm_input.py --flat-output-names` 실행 후 `window_summary.json` 생성
- `window_summary.json`에는 rollup dedup에 필요한 최소 `candidate_index`만 넣는다.
- `raw_log`, `raw_request`, `user_agent`, `referer`, response body, POST body, final verdict/success 판단은 복제하지 않는다.

### Rollup

- `src/sliding_window_rollup.py` v1.0 추가 완료.
- window_summary path 계산, missing/invalid window 기록, request_id dedup, candidate_index/distribution merge, `rollup_input.json`, `dedup_candidates.json`, `rollup_summary.json` 생성을 수행한다.
- `--overwrite` 지원.
- output 3종이 모두 있으면 기본 `skipped_existing`, 일부만 있으면 기본 실패.
- `uri_family_hints`, `low_and_slow_hints`, Stage1 projection은 v1.0에서 제외.
- rollup_id 생성은 기존 canonical 형식(`rollup_YYYYMMDD_HHMM_HHMM`)을 유지한다.
- 운영용 rollup naming을 실제 rollup/scheduler 생성 경로에 반영하는 작업(`--rollup-id-prefix` 등)은 지금 보류한다.

### Operator Queue

- `src/sliding_window_operator_queue.py` v1 추가 완료.
- 입력: `data/rollups/<date>/rollup_*/rollup_input.json`, `rollup_summary.json`.
- 출력: `data/operator_queue/<date>/queue_items.json`, `queue_summary.json`.
- quiet / needs_review / data_quality_check routing을 수행한다.
- data_quality_status, llm_eligible, top_observed distribution을 파생한다.
- `llm_required=false`를 operator queue 자체의 routing 의미로 유지한다.
- DB-backed MVP의 `full_report` job은 operator queue에서 멈추지 않고 Stage1/Stage2/viewer_payload까지 진행한다.
- `PAYLOAD_LIKE_REASON_HINTS`에 실제 관찰 prefix `sqli`, `xss`를 반영했다.
- `--rollup-pattern`을 추가해 운영용 rollup과 smoke/실험 rollup source selection을 분리할 수 있다.
- pattern 매칭 0개는 오류가 아니라 empty queue이며, quiet day로 계산하지 않는다.
- Operator Queue 자체는 보안 verdict/confidence/threat_level/success 판단을 생성하지 않는다.
