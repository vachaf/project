# 01_운영_기준_실행_가이드

- 문서 상태: 운영 기준 문서
- 목적: 최신 운영 기준에서 필요한 최소 실행/접속/이관 절차를 정리한다.

이 문서는 일반 운영자가 프로젝트를 홈 디렉터리 아래에 clone했다고 가정한다.  
고정 시스템 경로를 전제로 하지 않는다.

`scripts/generate_lab_traffic.py` v2는 authorized lab 전용 로그 원천 데이터 생성 도구이며, 실제 exploit 성공 검증 도구가 아니다.

## 1. 기본 설치 위치

공통 포맷:

```bash
cd ~
git clone https://github.com/vachaf/project
cd ~/project
```

이 문서의 모든 상대 경로는 `~/project` 기준이다.

```text
~/project/
├── config/
│   ├── .env.example
│   └── .env
├── data/
├── runs/
│   └── jobs/
├── logs/
├── src/
├── web/
└── .venv/
```

기준 경로:

- 프로젝트 루트: `~/project`
- env 예시: `~/project/config/.env.example`
- 실제 env: `~/project/config/.env`
- job 산출물: `~/project/runs/jobs/<job_id>/`
- 실행 로그: `~/project/logs/`

## 2. 서버 역할

- 웹서버: Apache 로그 생성, shipper 실행
- DB 서버: `web_logs` 저장
- LLM/Web 서버: Web UI 실행, job 조회, run artifact 확인

운영 기준:

- 표준 분석 진입점은 Web UI / job / run artifact 기준이다.
- export → prepare → stage1 → stage2 수동 실행 절차는 표준 운영 문서에서 안내하지 않는다.
- CLI 직접 실행은 개발자 디버그 또는 레거시 재현 절차로만 다룬다.
- Web UI는 read-only viewer이며, 분석 결과를 재계산하거나 새 관계를 추론하지 않는다.

## 3. env 파일 사용 정책

기준 파일은 `~/project/config/.env` 하나다.

최초 설정:

```bash
cd ~/project
cp config/.env.example config/.env
chmod 600 config/.env
```

적용:

```bash
cd ~/project
source .venv/bin/activate
set -a
source ./config/.env
set +a
```

운영 원칙:

- `config/.env` 하나만 사용한다.
- OpenAI / Anthropic 관련 값을 같은 파일 안에 함께 둔다.
- `LLM_PROVIDER`는 env 기본값으로 두지 않는다.
- provider 선택은 job/runner 또는 실행 계층에서 명시한다.
- 같은 셸에서 여러 env 파일을 번갈아 `source`하지 않는다.

`config/.env.example`은 위 정책을 따르는 기준 예시 파일이다.

## 4. shipper 실행

웹서버에서 실행한다.

프로젝트 안에 shipper가 있는 경우:

```bash
cd ~/project
set -a
source ./shipper.env
set +a

sudo -E python3 src/apache_log_shipper.py
```

`shipper.env`를 source한 환경변수가 Python 프로세스까지 전달되어야 하므로 `sudo -E`를 기본 예시로 사용한다.

환경에 따라 `sudo -E`가 변수를 보존하지 않으면 아래 fallback을 사용한다.

```bash
sudo bash -c 'cd "$HOME/project" && set -a && source ./shipper.env && set +a && exec python3 src/apache_log_shipper.py'
```

확인 포인트:

- Apache shipper 로그 반복 오류 여부
- DB row 증가 여부
- spool 누적 여부

## 5. Web UI 시작

운영 확인용:

```bash
cd ~/project
source .venv/bin/activate
set -a
source ./config/.env
set +a

uvicorn web.app:app --host 127.0.0.1 --port 8000
```

개발 중 자동 reload가 필요할 때만:

```bash
uvicorn web.app:app --reload --host 127.0.0.1 --port 8000
```

확인 URL:

```text
http://127.0.0.1:8000/
```

job 기준 확인:

```text
/job/<job_id>
/job/<job_id>/viewer
/job/<job_id>/artifact/viewer_payload
/job/<job_id>/artifact/stage2_report_md
```

예시:

```text
/job/5
/job/5/viewer
/job/5/artifact/viewer_payload
/job/5/artifact/stage2_report_md
```

## 6. Web UI 운영 원칙

- Web UI는 read-only viewer다.
- Web UI에서 pipeline 실행, DB export, report rewrite를 임의로 수행하지 않는다.
- Web UI에서 viewer_payload를 재생성하지 않는다.
- Web UI에서 severity/category/verdict를 재계산하지 않는다.
- Web UI에서 context-only 항목을 finding/incident로 승격하지 않는다.
- Web UI에서 Related Contexts/Supporting Events 관계를 새로 추론하지 않는다.
- `runs/jobs/<job_id>/` 아래의 artifact를 기준으로 표시한다.

## 7. job artifact 기준

기본 위치:

```text
~/project/runs/jobs/<job_id>/
```

대표 파일:

```text
manifest.json
export.json
llm_input.json
analysis_candidates.json
noise_summary.json
stage1_results.json
stage2_report_input.json
stage2_report.json
stage2_report.md
viewer_payload.json
```

Web UI는 위 artifact를 읽어 보여주는 viewer다.  
Web UI 표시를 위해 artifact 내용을 새로 추론하거나 보정하지 않는다.

## 8. DB 백업/이관

source DB 서버에서 export:

```bash
mysqldump -u root -p \
  --single-transaction \
  --routines \
  --triggers \
  web_logs > ~/backup.sql
```

Windows PowerShell에서 백업 파일 회수:

```powershell
scp user@192.168.56.109:~/backup.sql "$env:USERPROFILE\Downloads\backup.sql"
```

Windows PowerShell에서 target 서버로 업로드:

```powershell
scp "$env:USERPROFILE\Downloads\backup.sql" user@192.168.56.109:~/
```

target DB 서버에서 import:

```bash
sudo mysql -u root -p web_logs < ~/backup.sql
```

단순 운영에서는 아래 짧은 명령만 사용해도 된다.

```bash
mysqldump -u root -p web_logs > ~/backup.sql
sudo mysql -u root -p web_logs < ~/backup.sql
```

## 9. 표준 운영 순서

```text
Apache 로그 생성
-> shipper DB 적재
-> Web UI/job 기준 분석 결과 확인
-> /job/<job_id> detail 확인
-> /job/<job_id>/viewer 확인
-> 필요한 artifact 확인
```

표준 운영 문서에서는 export/prepare/stage1/stage2 개별 CLI 실행 절차를 안내하지 않는다.

## 10. 자주 헷갈리는 부분

- 프로젝트 루트는 일반적으로 `~/project`다.
- 고정 시스템 경로를 운영 문서의 기본값으로 쓰지 않는다.
- env 파일은 `config/.env` 하나만 사용한다.
- `config/.env.example`은 실제 운영 env의 기준 예시다.
- `LLM_PROVIDER`는 env 기본값으로 두지 않는다.
- Web UI는 결과 조회용 read-only viewer다.
- Web UI는 분석 결과를 새로 만들거나 수정하지 않는다.
- job 산출물은 `runs/jobs/<job_id>/` 기준이다.
