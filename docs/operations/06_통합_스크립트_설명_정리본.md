# 06_통합_스크립트_설명_정리본

- 문서 상태: 스크립트 참조 문서
- 목적: 현재 Python 코드 기준으로 각 스크립트의 역할, 입력, 출력, 연결 관계를 빠르게 확인한다.
- 실제 실행 명령은 [01_운영_기준_실행_가이드.md](./01_운영_기준_실행_가이드.md)를 우선한다.

## 1. 전체 흐름

### 1.1 수동 단계 흐름

```text
Apache 로그 생성
  -> apache_log_shipper.py
  -> MariaDB(web_logs)
  -> export_db_logs_cli.py
  -> prepare_llm_input.py
  -> llm_stage1_classifier.py
  -> llm_stage2_reporter.py
```

### 1.2 통합 실행 흐름

`run_analysis_pipeline.py`는 prepare -> stage1 -> stage2를 자동 실행한다.

- 시작점
  - `--export-input`
  - `--llm-input`
  - `--stage1-results`
- 중단점
  - `--stop-after prepare`
  - `--stop-after stage1`
  - `--stop-after stage2`
- dry-run
  - `--dry-run`
- 실행 기록
  - `pipeline_manifest.json`

## 2. 스크립트별 역할

### 2.1 `apache_log_shipper.py`

- Apache access/security/error 로그를 읽어 MariaDB `web_logs`에 적재한다.
- access/security/error를 각각 별도 테이블에 저장한다.
- DB flush 실패 시 spool 디렉터리에 임시 저장하고 재전송을 시도한다.

입력

- `APACHE_ACCESS_LOG`
- `APACHE_SECURITY_LOG`
- `APACHE_ERROR_LOG`
- `LOG_DB_*`
- `SHIPPER_*`

출력

- `apache_access_logs`
- `apache_security_logs`
- `apache_error_logs`
- spool 파일
- shipper app log

### 2.2 `export_db_logs_cli.py`

- MariaDB의 access/security/error 로그를 시간 범위 기준으로 JSON으로 export 한다.
- 사용자가 입력하는 시간 범위는 KST 기준이고, DB 조회는 UTC 저장값 기준으로 처리한다.
- 기본 table option은 `security`다.
- 출력 JSON 상위 키는 `meta`, `counts`, `data`다.

핵심 입력

- `--table`
- `--today`
- `--date`
- `--start`
- `--end`
- `--out-dir`
- `--out`

### 2.3 `prepare_llm_input.py`

- export JSON에서 분석 후보를 추린다.
- noise summary를 만든다.
- filtered out row는 선택적으로 저장한다.
- stage1 입력용 `*_llm_input.json`을 만든다.
- 같은 incident 중복 row를 dedup 한다.
- 기본 입력 source table은 `security`다.
- `--include-source-tables`로 포함 source table을 조정할 수 있다.

핵심 입력

- `--input`
- `--out-dir`
- `--base-name`
- `--min-score`
- `--min-repeat-aggregate`
- `--include-source-tables`
- `--write-filtered-out`

출력

- `<base>_llm_input.json`
- `<base>_analysis_candidates.json`
- `<base>_noise_summary.json`
- `<base>_filtered_out_rows.json` 선택

context-only 문맥

- `supporting_events`
- `probing_sequence_summaries`
- `ip_behavior_aggregates`
- `auth_behavior_summaries`
- `method_behavior_summaries`
- `protocol_anomaly_summaries`
- `static_baseline_summaries`
- `crawler_baseline_summaries`
- `sensitive_path_probe_summaries`
- `mixed_baseline_scanner_summaries`

위 문맥 항목은 성공/침해 단정 근거가 아니라 문맥 보존용이다.

### 2.4 `llm_stage1_classifier.py`

- `analysis_candidates`를 순회하며 후보별 1차 분류를 수행한다.
- provider는 `--provider` 또는 `LLM_PROVIDER`로 정해지며, 기본 fallback은 OpenAI다.
- Anthropic provider는 `--model` 또는 `ANTHROPIC_MODEL`이 필요하다.

핵심 입력

- `--input`
- `--provider`
- `--model`
- `--candidate-limit`
- `--max-evidence-items`
- `--reasoning-effort`
- `--dry-run`
- `--store`

출력

- `<base>_stage1_results.json`
- `<base>_stage1_errors.json`

dry-run 기준

- `llm_stage1_classifier.py --dry-run`은 실제 API 호출 없이 요청 계획 성격의 결과를 만든다.
- `run_analysis_pipeline.py --dry-run`은 Stage1 dry-run 산출물이 일반 `results` 구조가 아닐 때 placeholder 결과를 만들어 Stage2 dry-run까지 이어질 수 있게 한다.

### 2.5 `llm_stage2_reporter.py`

- `--stage1-results`를 필수 입력으로 받아 incident 요약 보고서를 생성한다.
- `--llm-input`은 선택 입력이며 prepare 문맥을 더 풍부하게 전달할 때 사용한다.
- `--stage1-errors`는 선택 입력이다.
- `--known-asset-ips`는 선택 문맥이며 env fallback을 사용할 수 있다.
- Stage2는 raw evidence 원문 뷰어가 아니라 incident 요약 보고서 생성기다.
- raw evidence는 prepare/stage1에서 더 직접적으로 사용되고, Stage2에서는 사건형 요약 입력으로 축약된다.
- suspicious incident는 최종 판단 전 `request_id` 기준 raw log, error log, 앱 로그 대조가 필요하다.

핵심 입력

- `--stage1-results`
- `--llm-input`
- `--stage1-errors`
- `--provider`
- `--model`
- `--top-incidents`
- `--top-noise-groups`
- `--top-ips`
- `--known-asset-ips`
- `--reasoning-effort`
- `--dry-run`
- `--store`

출력

일반 출력:

- `<base>_stage2_report_input.json`
- `<base>_stage2_report.json`
- `<base>_stage2_report.md`

실패 또는 parse error 시 생성될 수 있는 출력:

- `<base>_stage2_report_error.json`
- `<base>_stage2_report_raw_error.json`

Anthropic 참고

- `stop_reason=max_tokens`면 truncation 가능성을 먼저 본다.
- 정상 종료 여부는 report JSON의 `meta` 또는 raw/error dump의 provider, model, response, stop reason으로 확인한다.

### 2.6 `run_analysis_pipeline.py`

- prepare -> stage1 -> stage2를 자동 실행한다.
- export JSON, llm input, stage1 results 중 하나에서 시작할 수 있다.
- `--stop-after`로 prepare/stage1/stage2 중 원하는 단계에서 멈출 수 있다.
- `--prepare-source-tables` 기본값은 `auto`다.
  - `--export-input` 경로에서는 export JSON `meta.table_option/counts/data`를 읽어 prepare 포함 table을 자동 결정한다.
  - explicit override를 주면 그 값이 우선한다.
  - `--llm-input`/`--stage1-results` resume 경로 또는 export read 실패 시 `security` fallback을 사용한다.
- 기본 중간 산출물 디렉터리는 `<work-dir>/data/processed`다.
- 기본 보고서 디렉터리는 `<work-dir>/reports`다.
- 실행 후 `pipeline_manifest.json`을 생성한다.

시작점

- `--export-input`
- `--llm-input`
- `--stage1-results`

중단점

- `--stop-after prepare`
- `--stop-after stage1`
- `--stop-after stage2`

핵심 입력

- `--work-dir`
- `--processed-dir`
- `--reports-dir`
- `--llm-provider`
- `--stage1-model`
- `--stage2-model`
- `--known-asset-ips`
- `--dry-run`
- `--keep-going`

manifest 요약

- `pipeline_manifest.json`에는 입력 시작점, 실행 단계, command, 산출물 경로, provider, known asset IP 등이 기록된다.
- table 자동 해석 관련 meta를 함께 기록한다.
  - `prepare_source_tables_requested`
  - `prepare_source_tables_resolved`
  - `prepare_source_tables_resolution_reason`

## 4. 현재 분석 기준

### 4.1 `security` / `error` / `access` 역할

- 수동 `prepare_llm_input.py` 기준 기본 prepare 입력은 `security`다.
- `run_analysis_pipeline.py --export-input` 기준 기본값은 auto resolution이다.
- `error`와 `access`는 보조 분석, 상관분석, 운영 확인용이다.
- 필요 시 수동 prepare에서는 `--include-source-tables`, pipeline에서는 `--prepare-source-tables`로 포함 범위를 조정할 수 있다.
- `access`를 현재 주 입력으로 보지 않는다.

### 4.2 logs-only 한계

- 분석 기준은 Apache 로그 표면에 직접 남는 신호다.
- raw POST body, response body 원문, DB 결과, 브라우저 실행 여부는 기본 근거로 사용하지 않는다.
- `status_code`, `response_body_bytes`, `resp_content_type`만으로 성공, 침해, 유출을 단정하지 않는다.

### 4.3 `resp_html_*`와 보수 해석 기준

- `resp_html_*` fingerprint 계열은 현재 보류 또는 선택 항목이다.
- 핵심 근거처럼 사용하지 않는다.
- 현재 우선 보는 보수 해석 기준은 아래다.
  1. `resp_content_type`
  2. `response_body_bytes`
  3. `raw_request_target`
  4. `path_normalized_from_raw_request`
  5. `likely_html_fallback_response`

### 4.4 context-only 문맥의 의미

- `supporting_events`와 각 summary 계열은 candidate를 늘리는 용도가 아니라 맥락을 보존하는 용도다.
- 반복 auth 실패, method behavior, protocol anomaly, static/crawler/scanner baseline 같은 문맥을 보수적으로 전달한다.
