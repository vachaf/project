## 1. 작업 목표

Apache를 웹단으로 사용하는 여러 앱 배치에서 동일한 `apache_security_io_v1` Custom LogFormat을 적용하고, 앱별로 Apache 로그에서 무엇이 관찰되는지 비교하기 위한 기반을 만들었다.

중점은 취약점 성공 판정이 아니라 다음 구분이다.

```text
Apache request/response metadata로 관찰 가능한 것
Apache error log까지 붙이면 보강 가능한 것
앱/WAF/DB/backend audit 없이는 단정하면 안 되는 것
```

핵심 정리:

- 앱별로 LogFormat을 나누지 않고 공통 포맷을 유지한다.

- Cookie, Authorization, Set-Cookie, request body, response body 원문은 기본 제외한다.
- `status_code=200`, `response_body_bytes`, `resp_content_type`, `handler`만으로 성공/노출/침해를 단정하지 않는다.

## 5. OpenCart 결과

- run_id: `obs_opencart_002`
- target_app: `opencart`
- topology: `apache_php`
- log_format: `apache_security_io_v1`

결과:

- S01~S15 전체 관측 성공
- `O0=0`, `O1=13`, `O1/O4=2`
- `apache_security_io_v1` 필드 전체 관찰 성공
- warn/error-level Apache/PHP error context는 관찰되지 않음
- S12 scanner_burst는 logical path 7개였지만 `/admin` redirect-follow로 actual Apache request 8개가 관찰됨

OpenCart 특성:

- `.htaccess`/front-controller rewrite의 영향으로 없는 경로나 probe-like path도 `status_code=200`으로 관찰될 수 있다.
- `query_string`에 `_route_=`가 추가되어 OpenCart routing/fallback의 관찰 힌트가 된다.
- `handler=redirect-handler`가 다수 관찰됐다.

해석:

```text
status_code=200 + handler=redirect-handler + _route_=... 조합은
공격 성공이 아니라 fallback/routed response 후보로 해석해야 한다.
```

## 6. Juice Shop reverse proxy 결과

- run_id: `obs_juiceshop_proxy_001`
- target_app: `juiceshop`
- topology: `apache_reverse_proxy_node`
- log_format: `apache_security_io_v1`

결과:

- S01~S15 전체 관측 성공
- `O0=0`, `O1=13`, `O1/O4=2`
- `apache_security_io_v1` 필드 전체 관찰 성공
- 대부분 `status_code=200` + `handler=proxy-server`로 관찰됨
- 정규 run에서는 warn/error-level proxy context가 관찰되지 않음

Juice Shop 특성:

- Apache는 backend Juice Shop의 내부 결과를 알 수 없고, backend response metadata만 관찰한다.
- probe-like path도 backend/SPA fallback으로 `status_code=200`을 반환할 수 있다.
- `handler=proxy-server`는 reverse proxy topology 해석의 핵심 힌트다.

별도 proxy error check:

```bash
sudo docker stop juice-shop
curl -i -H 'User-Agent: proxy-error-check/1.0' http://juiceshop.local/
sudo tail -n 20 /var/log/apache2/juiceshop_error.log
sudo docker start juice-shop
```

관찰:

```text
HTTP/1.1 503 Service Unavailable
[module_name:proxy] [log_level:error] AH00957: attempt to connect to 127.0.0.1:3000 failed
[module_name:proxy_http] [log_level:error] AH01114: failed to make connection to backend: 127.0.0.1
```

해석:

```text
503/proxy error는 backend availability context이며,
공격 성공/침해 증거로 해석하지 않는다.
```

## 9. 3-way 비교 결론

비교 문서:

- `lab/observability/comparison_php_sample_vs_opencart.md`

주요 결론:

- 동일한 `apache_security_io_v1` 포맷을 유지해야 앱별 배치 차이가 선명하게 보인다.

- `status_code=200`은 topology-dependent weak signal이며, 공격 성공/유출/내부 결과의 근거로 사용하지 않는다.

- proxy/backend error만으로 침해 판단 금지
