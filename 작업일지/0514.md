## 1. 작업 목표

Apache를 웹단으로 사용하는 여러 앱 배치에서 동일한 `apache_security_io_v1` Custom LogFormat을 적용하고, 앱별로 Apache 로그에서 무엇이 관찰되는지 비교하기 위한 기반을 만들었다.

중점은 취약점 성공 판정이 아니라 다음 구분이다.

```text
Apache request/response metadata로 관찰 가능한 것
Apache error log까지 붙이면 보강 가능한 것
앱/WAF/DB audit 없이는 단정하면 안 되는 것
```

핵심 정리:

- 범위는 reverse proxy 전용이 아니라 웹단에 Apache HTTP Server를 사용하는 앱 전반이다.
- 앱별로 LogFormat을 나누지 않고 공통 포맷을 유지한다.
- `apache_security_core_v1` / `apache_security_io_v1` 계약을 정의했다.
- Cookie, Authorization, Set-Cookie, request body, response body 원문은 기본 제외한다.
- `status_code=200`, `response_body_bytes`, `resp_content_type`, `handler`만으로 성공/노출/침해를 단정하지 않는다.

## 4. PHP sample baseline 결과

- run_id: `obs_php_sample_002`
- target_app: `php_sample`
- topology: `apache_php`
- log_format: `apache_security_io_v1`

결과:

- S01~S15 전체 관측 성공
- `app_security.filtered.log`: 21 lines
- `app_access.filtered.log`: 21 lines
- `app_error.by_request_id.log`: 15 lines
- `request_id` 기반 security/error 연결 확인
- notice-level app/PHP context와 warn/error-level context 분리 확인
- `/server-status`는 localhost-originated request에서 200이었으나 외부 client 확인은 403으로 확인

해석:

- PHP sample은 direct Apache/PHP/static baseline으로 적합하다.
- `/error.php`는 500 + PHP warning을 발생시켜 O2 케이스 확인에 유용했다.
- S08/S09는 요청 metadata로는 관찰되지만 로그인 성공/업로드 저장 성공 판단은 app/DB audit 없이는 금지한다.

## 5. OpenCart 결과

- run_id: `obs_opencart_002`
- target_app: `opencart`
- topology: `apache_php`
- log_format: `apache_security_io_v1`

결과:

- S01~S15 전체 관측 성공
- `O0=0`, `O1=13`, `O1/O4=2`
- `apache_security_io_v1` 필드 전체 관찰 성공
- warn/error-level Apache/PHP error context는 관찰되지 않음
- S12 scanner_burst는 logical path 7개였지만 `/admin` redirect-follow로 actual Apache request 8개가 관찰됨

OpenCart 특성:

- `.htaccess`/front-controller rewrite의 영향으로 없는 경로나 probe-like path도 `status_code=200`으로 관찰될 수 있다.
- `query_string`에 `_route_=`가 추가되어 OpenCart routing/fallback의 관찰 힌트가 된다.
- `handler=redirect-handler`가 다수 관찰됐다.

해석:

```text
status_code=200 + handler=redirect-handler + _route_=... 조합은
공격 성공이 아니라 fallback/routed response 후보로 해석해야 한다.
```

## 6. PHP sample vs OpenCart 비교 결론

비교 문서:

- `lab/observability/comparison_php_sample_vs_opencart.md`

주요 결론:

- 동일한 `apache_security_io_v1` 포맷을 유지해야 앱별 배치 차이가 선명하게 보인다.
- PHP sample은 직접 처리 baseline으로 단순하고, 파일 존재/404/500 관찰이 직관적이다.
- OpenCart는 실제 PHP 앱의 rewrite/front-controller 특성 때문에 200 응답이 약한 성공 신호다.
- OpenCart-like 앱에서는 `_route_=`, `handler=redirect-handler`, redirect-follow 여부를 context feature 후보로 다룰 필요가 있다.
