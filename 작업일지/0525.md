- empty queue는 quiet day가 아니다.

- score/verdict_hint/severity/category/confidence/threat_level을 새로 만들지 않는다.


### Operator Queue `--rollup-pattern` 구현

- `src/sliding_window_operator_queue.py`에 `--rollup-pattern` 옵션을 추가했다.
- 기본값은 기존 동작과 호환되도록 `rollup_*`로 유지했다.
- Python `fnmatch` 기반으로 rollup directory basename만 필터링한다.
- path 전체가 아니라 directory name에만 pattern을 적용한다.
- pattern에 매칭되는 rollup directory만 queue item 후보가 된다.
- `queue_items.json`과 `queue_summary.json`에 `source_selection` metadata를 추가했다.
- CLI text output에도 `source_selection`을 출력한다.
- `skipped_existing`일 때는 기존 `queue_summary.json`에 저장된 `source_selection`을 반환하도록 했다.

  - empty queue는 quiet으로 집계되지 않는다.
  - source_selection metadata가 queue artifacts와 결과 summary에 남는다.

### Rollup naming generation 판단

- `--rollup-id-prefix`를 지금 추가하지 않기로 결정했다.
- `src/sliding_window_rollup.py`의 기본 rollup_id 생성은 기존 canonical 형식인 `rollup_YYYYMMDD_HHMM_HHMM`을 유지한다.
- `rollup_ops_*`, `rollup_smoke_*` naming은 문서상 후보/운영 label로만 둔다.
- 판단 근거:
  - Operator Queue v1에서 `--rollup-pattern`으로 source selection이 가능하다.
  - 생성 시점에 naming/prefix를 강제하면 scheduler, cron, smoke 실행, 사용자 명령에 prefix 의미가 퍼져 복잡도가 증가한다.
  - 운영자는 queue에서 `quiet`, `needs_review`, `data_quality_check`, `llm_eligible`를 먼저 봐야 한다.
  - 운영자가 rollup_id prefix 의미를 알아야만 queue를 해석하는 구조는 피한다.
  - 현재 단계의 핵심은 rollup 이름을 더 세분화하는 것이 아니라 사람이 queue를 보고 무엇을 판단할지 정리하는 것이다.
- 재검토 조건:
  - Queue item detail 설계가 안정화된 뒤
  - Single Rollup Observation Brief가 안정화된 뒤
  - 실제 운영 cadence/profile이 필요해진 뒤
  - naming 없이 운영 혼선이 반복적으로 발생한 뒤

6. 수동 smoke 결과

### 운영용 pattern smoke

명령:

```bash
python3 src/sliding_window_operator_queue.py \
  --work-dir /opt/web_log_analysis \
  --date 2026-05-24 \
  --rollup-pattern "rollup_ops_*" \
  --overwrite \
  --pretty
```

결과:

```text
[QUEUE] status=written
[QUEUE] date=2026-05-24
[QUEUE] out_dir=data/operator_queue/2026-05-24
[QUEUE] queue_items=data/operator_queue/2026-05-24/queue_items.json
[QUEUE] queue_summary=data/operator_queue/2026-05-24/queue_summary.json
[QUEUE] source_selection: rollup_root=data/rollups/2026-05-24 rollup_pattern=rollup_ops_* matched_rollup_count=0
[QUEUE] summary: status=written rollup_items_total=0 quiet=0 needs_review=0 data_quality_check=0 llm_eligible=0 llm_required=0
```

해석:

- 현재 `2026-05-24`에는 `rollup_ops_*`에 매칭되는 운영용 rollup이 없다.
- queue는 empty로 생성된다.
- 이것은 오류가 아니다.
- 이것은 quiet day가 아니다.

### 전체 rollup pattern smoke

명령:

```bash
python3 src/sliding_window_operator_queue.py \
  --work-dir /opt/web_log_analysis \
  --date 2026-05-24 \
  --rollup-pattern "rollup_*" \
  --overwrite \
  --pretty
```

결과:

```text
[QUEUE] status=written
[QUEUE] date=2026-05-24
[QUEUE] out_dir=data/operator_queue/2026-05-24
[QUEUE] queue_items=data/operator_queue/2026-05-24/queue_items.json
[QUEUE] queue_summary=data/operator_queue/2026-05-24/queue_summary.json
[QUEUE] source_selection: rollup_root=data/rollups/2026-05-24 rollup_pattern=rollup_* matched_rollup_count=2
[QUEUE] summary: status=written rollup_items_total=2 quiet=0 needs_review=2 data_quality_check=0 llm_eligible=2 llm_required=0
```

해석:

- 기존 smoke/실험 rollup 2개가 전체 pattern에 포함된다.
- 두 item 모두 `needs_review`로 라우팅된다.
- 이 결과는 smoke artifact까지 포함한 전체 조회 결과다.
