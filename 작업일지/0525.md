3. 유지할 원칙
- Apache logs-only evidence boundary를 유지한다.
- Operator Queue는 보안 verdict가 아니라 review routing artifact다.
- `--rollup-pattern`은 queue 입력 선택 기능이며 보안 의미를 만들지 않는다.
- `rollup_ops_*`, `rollup_smoke_*` 같은 naming은 운영/실험 artifact 구분용 label일 뿐 공격/침해/성공 의미가 아니다.
- empty queue는 quiet day가 아니다.
- quiet은 rollup이 존재하고 `candidate_index_count=0`인 경우에만 해당한다.
- `llm_required=false`를 유지한다.
- Stage1/Stage2/LLM reporter/Web UI/DB/API를 실행하지 않는다.
- score/verdict_hint/severity/category/confidence/threat_level을 새로 만들지 않는다.
- context-only를 finding/incident로 승격하지 않는다.
- rollup 생성 시점에 naming policy를 강제하지 않는다.
- Observation Brief는 Stage2 report가 아니며 detection engine도 아니다.
- Queue item detail CLI preview는 새 artifact를 만들지 않고 stdout 출력만 수행한다.

4. 완료 내용

### Operator Queue source selection 문서화

- `docs/design/99_sliding_window_operator_queue_design.md`에 `Queue source selection / cadence 분리` 섹션을 추가했다.
- Operator Queue의 기본 의미를 다음처럼 정리했다.

```text
Operator Queue = 운영자가 먼저 볼 운영용 rollup 목록
```

- smoke/실험 rollup은 기본 운영 queue에 섞지 않는다는 원칙을 추가했다.
- empty queue semantics를 문서화했다.

```text
matched_rollup_count=0
rollup_items_total=0
quiet=0
needs_review=0
data_quality_check=0
llm_eligible=0
llm_required=0
```

- `empty queue != quiet day` 원칙을 명시했다.
- `source_selection` metadata 후보를 문서화했다.

```json
{
  "source_selection": {
    "rollup_root": "data/rollups/2026-05-24",
    "rollup_pattern": "rollup_ops_*",
    "matched_rollup_count": 0
  }
}
```

### Operator Queue `--rollup-pattern` 구현

- `src/sliding_window_operator_queue.py`에 `--rollup-pattern` 옵션을 추가했다.
- 기본값은 기존 동작과 호환되도록 `rollup_*`로 유지했다.
- Python `fnmatch` 기반으로 rollup directory basename만 필터링한다.
- pattern에 매칭되는 rollup directory만 queue item 후보가 된다.
- `queue_items.json`과 `queue_summary.json`에 `source_selection` metadata를 추가했다.
- CLI text output에도 `source_selection`을 출력한다.
- `skipped_existing`일 때는 기존 `queue_summary.json`에 저장된 `source_selection`을 반환하도록 했다.

### Rollup naming generation 판단

- `--rollup-id-prefix`를 지금 추가하지 않기로 결정했다.
- `src/sliding_window_rollup.py`의 기본 rollup_id 생성은 기존 canonical 형식인 `rollup_YYYYMMDD_HHMM_HHMM`을 유지한다.
- `rollup_ops_*`, `rollup_smoke_*` naming은 문서상 후보/운영 label로만 둔다.
- 판단 근거:
  - Operator Queue v1에서 `--rollup-pattern`으로 source selection이 가능하다.
  - 생성 시점에 naming/prefix를 강제하면 scheduler, cron, smoke 실행, 사용자 명령에 prefix 의미가 퍼져 복잡도가 증가한다.
  - 운영자는 queue에서 `quiet`, `needs_review`, `data_quality_check`, `llm_eligible`를 먼저 봐야 한다.
  - 현재 단계의 핵심은 rollup 이름을 더 세분화하는 것이 아니라 사람이 queue를 보고 무엇을 판단할지 정리하는 것이다.
