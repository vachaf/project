## 3. 작업 내용 (담당자 구분)

### [XSS Hint Split] (김현경)
* **XSS hint split 계획 수립**: XSS pattern/constants 중 1차 분리 가능한 범위를 검토하고, browser execution이나 client-side JavaScript 실행 성공을 Apache logs-only로 단정하지 않는 기준을 유지함
* **XSS hint patterns 분리 완료**: XSS 관련 구조적 패턴과 educational XSS search helper 계열을 별도 prepare 모듈로 분리함
* **해석 경계 유지**: `onerror`, `<script>`, HTML entity 등은 XSS 의심 정황으로만 취급하고, 브라우저 실행 여부나 실제 XSS 성공 여부는 단정하지 않도록 유지함
* **wrapper/import 호환성 유지**: 기존 `prepare_llm_input.py` 호출 구조가 깨지지 않도록 wrapper와 import fallback 구조를 보존함

### [File Disclosure Hint Split] (김현경)
* **file disclosure hint 후보 검토**: path traversal, PHP wrapper, sensitive path/file access 의심 패턴 중 1차 분리 가능한 항목을 검토함
* **file disclosure hint patterns 분리 완료**: 파일 노출 의심 관련 pattern/constants를 별도 prepare 모듈로 분리함
* **Apache logs-only 한계 유지**: response body 원문, 파일 내용, 실제 파일 노출 성공, 서버 내부 파일 존재 여부는 access log만으로 확인할 수 없다는 기준을 유지함
* **기존 scoring/filtering 영향 최소화**: hint pattern 이동만 수행하고 candidate scoring, filtering, supporting_events 연결 로직은 변경하지 않음

### [Traversal / CMDI Hint Split] (김현경)
* **traversal·CMDI hint split 범위 검토**: shared pattern과 scoring 경계가 있는 항목을 확인하고, 직접 분리 가능한 pattern/constants 중심으로 범위를 제한함
* **traversal·CMDI hint patterns 분리 완료**: directory traversal 및 command injection 의심 패턴을 별도 prepare 모듈로 분리함
* **성공 단정 방지 유지**: `../`, encoded traversal, shell metacharacter, command-like token은 의심 정황으로만 취급하고, 파일 읽기 성공이나 command execution 성공은 단정하지 않도록 유지함
* **automation/shared policy 영역은 보류**: 여러 hint 계열에서 공유되는 attack/search policy, decoded hint logic, scoring/FP verdict 경계는 추가 분리하지 않음

### [Shared Attack Policy Boundary Review] (김현경)
* **공유 정책 경계 검토**: SQLi/XSS/file disclosure/traversal·CMDI hint split 이후 남은 shared attack/search policy constants와 helper들의 분리 가능성을 검토함
* **추가 분리 보류 결정**: decoded attack hints, shared scoring, supporting_events 생성/연결, FP verdict 관련 로직은 evidence boundary 위험이 커서 즉시 분리하지 않음
* **prepare split 안정성 우선**: 현재 단계에서는 mechanical refactor가 가능한 pattern/constants 분리까지만 완료하고, 의미 변경 가능성이 있는 로직은 유지함

### [Auth / Crawler Constants Mini-move] (김현경)

* **crawler baseline constants 이동**: crawler baseline summary에서 owner가 명확한 constants를 `src/prepare/crawler_baseline.py` 쪽으로 이동함
* **해석 제한 유지**: auth behavior는 로그인 성공, 계정 탈취, lockout 발동을 의미하지 않으며, crawler baseline은 실제 crawler 신원이나 사이트 구조 확정을 의미하지 않는다는 기준을 유지함
