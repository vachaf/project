1. 작업날짜: 2026.5.24

2. 오늘목표:

3. 유지할 원칙
- Apache logs-only evidence boundary를 유지한다.
- `status_code=200`으로 공격 성공/침해 성공을 단정하지 않는다.
- `status_code=403/404/500/503`만으로 취약점/공격 성공/침해를 단정하지 않는다.
- `response_body_bytes`, `resp_content_type`, `text/html`로 파일 노출/정보 유출을 단정하지 않는다.
- POST metadata만으로 로그인 성공/업로드 저장 성공을 단정하지 않는다.
- raw POST body, response body, DB 결과, browser execution을 추론하지 않는다.
- context-only를 finding/incident로 승격하지 않는다.
- Web UI에서 severity/category/verdict를 재계산하지 않는다.
- prepare/scoring/filtering 변경은 하지 않는다.
- Sliding Window는 운영 자동화와 token/cost 제어 설계로만 다룬다.

4. 완료 내용
- `src/sliding_window_scheduler.py --mode prepare`를 추가했다.
- prepare mode는 window별 `export.json` 존재 여부를 확인한다.
- prepare mode는 `prepare_llm_input.py --flat-output-names`를 호출한다.
- prepare mode의 `--out-dir`은 window root로 지정한다.
- prepare mode는 `llm_input.json`, `analysis_candidates.json`, `noise_summary.json` 생성 여부를 확인한다.
- prepare mode는 stage1/stage2/viewer_payload를 실행하지 않는다.
- prepare mode는 `runs/`를 생성하지 않는다.
- 보수적 상태 정책을 추가했다.
  - `export.json` 없음 → `missing_export`, 기본 stop
  - output 3종 모두 이미 있음 → `skipped_existing`
  - output 일부만 있음 → `partial_existing`, 기본 stop
  - prepare 실행 성공 후 output 누락 → `missing_output`
  - `--overwrite` → 기존 output이 있어도 재실행 허용
  - `--keep-going` → 실패 후 다음 window 계속 처리
- `tests/test_sliding_window_scheduler.py`를 확장했다.
  - prepare command가 `prepare_llm_input.py`를 호출하는지 검증
  - `--input`이 window `export.json`인지 검증
  - `--out-dir`이 window root인지 검증
  - `--flat-output-names`가 들어가는지 검증
  - `runs/` 경로가 없는지 검증
  - 기존 output 3종이 있으면 skip되는지 검증
  - `export.json`이 없으면 `missing_export`인지 검증
  - partial existing output이면 `partial_existing`인지 검증
  - prepare 성공 후 output 누락이면 `missing_output`인지 검증
- 테스트 실패 1건을 수정했다.
  - `test_prepare_mode_skips_when_all_flat_outputs_exist`에서 두 번째 window fake prepare가 output 3종을 만들지 않아 `missing_output`이 되는 문제가 있었다.
