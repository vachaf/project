## DB-backed full_report MVP smoke 기록

- Web UI에서 `analysis_jobs` job 등록 후 shell에서 Analysis Job Worker를 실행해 실제 `full_report` direct pipeline을 확인했다.

```bash
python3 src/analysis_job_worker.py --once --worker-id smoke-real --run-pipeline
```

- 확인된 흐름:

```text
analysis_jobs(PENDING)
  -> Analysis Job Worker claim
  -> export_db_logs_cli.py
  -> run_analysis_pipeline.py direct path
  -> prepare
  -> Stage1
  -> Stage2
  -> viewer_payload
  -> analysis_reports 저장
  -> analysis_jobs(SUCCEEDED)
  -> /job/{id}/viewer dashboard 표시
```

- job_id=5 기준 `analysis_reports` 저장값:

  - `stage2_report_path = runs/jobs/5/stage2_report.json`

  - `viewer_payload_path = runs/jobs/5/viewer_payload.json`

## no-data smoke

- empty export job은 full pipeline을 실행하지 않고 no-data completion으로 닫히는 것을 확인했다.
- 확인 결과:
  - `JOB_NO_DATA` event 기록
  - `analysis_jobs.status=SUCCEEDED`
  - `analysis_reports.summary` 저장
  - `export_path`만 저장
  - stage/viewer paths는 `NULL`
  - `runs/jobs/<id>/export.json`만 생성

## 범위 정리

- 이번 smoke는 DB-backed `full_report` direct pipeline 기준이다.
- `full_report` worker에는 `sliding_window / rollup / operator_queue`를 자동 삽입하지 않는다.
- `windowed_triage`와 operator queue 기반 triage 연결은 후속 mode로 유지한다.
