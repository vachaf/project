### [새 공격 coverage candidate review 작성] (공동)
* **신규 문서 작성**: `docs/design/99_prepare_new_attack_coverage_candidate_review.md`를 작성함
* **문서 역할 고정**: 이 문서는 구현 계획서가 아니라 candidate review 문서로 두고, 어떤 공격/시나리오 family를 먼저 fixture/regression coverage 후보로 다룰지 비교하는 용도로 정리함
* **후보 비교 정리**:
  * SSRF / metadata endpoint attempt
  * Log4Shell / JNDI lookup
  * SSTI / template injection
  * Webshell / admin tool probe
  * Deserialization / object injection-like payload
  * XXE / XML parser abuse attempt
  * Open redirect / redirect abuse attempt
  * request smuggling / header anomaly attempt
  * API key / secret token probe
  * GraphQL / API introspection attempt
  * LDAP / NoSQL injection-like payload
  * traversal/CMDI 보강 후보
  * file disclosure 보강 후보
  * scanner/tool behavior summary 확장 후보
* **공통 경계 문서화**: 각 후보마다 Apache access logs alone으로 볼 수 있는 것과 볼 수 없는 것을 나누고, 공격 성공/침해/유출/RCE/브라우저 실행/내부망 접근 성공은 단정하지 않는 원칙을 고정함
* **단기 우선순위 정리**: SSRF, Log4Shell, Webshell 계열을 단기 P1 후보로 정리함
* **중기/장기 우선순위 정리**: SSTI, XXE, Open redirect, GraphQL, API key probe는 중기 P2로, deserialization, LDAP/NoSQL injection-like, request smuggling, scanner/tool behavior 확장은 장기 P3로 정리함
