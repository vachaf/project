## 아직 결정하지 않은 항목

### status/error-only demotion 실제 prepare 반영 여부

- 보류한다.
- 이유:
  - error/status metadata는 일부 실제 공격 시도에서 보조 신호로 유효할 수 있다.
  - broad demotion은 recall 손실 가능성이 있다.
  - 먼저 diagnostic output과 regression을 더 축적한다.

### scanner/probe demotion 실제 prepare 반영 여부

- 보류한다.
- 이유:
  - scanner/probe context는 sensitive path probing, mixed baseline, probing sequence summary에서 유용하다.
  - context-only를 finding으로 승격하지 않는 원칙과 별개로, prepare candidate visibility를 너무 일찍 낮추면 관찰성이 줄 수 있다.
  - 명시적 payload와 단순 probe를 분리하는 diagnostic 기준을 먼저 안정화한다.

## Apache logs-only guardrail

- `status_code=200`으로 공격 성공/침해 성공을 단정하지 않는다.
- `response_body_bytes`, `resp_content_type`, `text/html`만으로 파일 노출/정보 유출을 단정하지 않는다.
- POST metadata만으로 로그인 성공, 업로드 저장 성공, 계정 장악, DB 영향, 서버 내부 상태 변화를 단정하지 않는다.
- raw POST body, response body, DB 결과, 브라우저 실행 여부는 Apache logs-only 입력에 없으므로 추론하지 않는다.
- context-only 항목을 finding/incident로 승격하지 않는다.
- Web UI는 read-only display/interpretation aid 범위로 유지하고, severity/category/verdict를 재계산하지 않는다.
